# CH.4 v3 — 뷰파인더 여백 · DIGITAL / FILM 프레임 리디자인

기반: CH.4 v2 (`camera_ch4_viewfinder_refine_v2.zip`). 사진/동영상 촬영, 필터, 원본 동시 저장, 갤러리, 권한·전환 로직은 보존합니다.

## 이번 수정

- **프리뷰 바깥 여백:** 촬영 화면에 좌우 13px / 위아래 12px 여백을 확보하고, 얇은 카메라 바디 베젤과 그림자를 추가했습니다. **4:3·16:9·1:1 화면비는 유지**하며 프리뷰를 늘이거나 왜곡하지 않습니다.
- **필카 디자인 전체 교체:** 기존 크고 반복되는 필름 구멍, `35MM`, `35/02`, 프레임 번호, 긴 필름 텍스트를 제거했습니다. 대신 어두운 네거티브 게이트 마트, 아주 얇은 이미지 창 테두리, 작은 측면 레지스트레이션 표식과 아래쪽 미세한 라인만 남겼습니다.
- **디카 프레임 절제:** 여러 군데에 흩어져 있던 HUD 텍스트를 제거했습니다. 얇은 디지털 뷰파인더 선과 하단의 작은 **날짜 / 현재 색감**만 남겼고, 두 라벨은 *사진 위가 아닌 어두운 불투명 마트 위*에 표시하여 가독성을 확보했습니다.
- **줌 컨트롤 간소화:** 평소에는 우측에 현재 배율 동그란 버튼 1개만 표시됩니다. 탭하면 배율 버튼과 세로 슬라이더가 열리고, X를 누르면 접힙니다. **확장해도 프리뷰 크기는 바뀌지 않습니다.**
- **상단 바 소폭 축소:** 48px → 45px. 사진·영상 공통 조작 위치 유지, 설정 패널은 기존대로 미리보기 위에 표시됩니다.
- **프레임 저장 일치:** `lib/widgets/frame_artwork.dart`의 *동일한 CustomPainter*가 촬영 미리보기와 내보내기용 투명 PNG 프레임을 그립니다. 사진(JPG)은 이미지 합성, 영상(MP4)은 기존 FFmpeg PNG 합성 경로를 이용합니다. 프레임 적용 여부를 끄면 저장본에만 프레임이 빠지며 **미리보기 프레임은 계속 표시**됩니다.
- **원본 보존:** `필터 + 원본 동시 저장`을 켜면 원본 저장 파일에는 필터와 프레임을 적용하지 않습니다(기존 정책 유지).

## 수정 파일

- `lib/widgets/frame_artwork.dart` — 디카/필카 공통 내보내기 프레임 재디자인
- `lib/screens/camera_screen.dart` — 화면 바깥 여백, 베젤, 한 버튼으로 접는 줌, 얇은 상단바
- `lib/widgets/camera_chrome.dart` — 필카 필터 카드의 `35MM` 표기 → `FILM`
- `lib/screens/settings_screen.dart` — 저장 프레임 설명 문구 최신화

## 적용 (Windows PowerShell)

먼저 `git add .; git commit -m "Before CH4 v3"` 로 현재 작업을 백업합니다.
ZIP의 `lib` 폴더를 프로젝트 루트에 덮어쓰고, 다음 명령을 실행합니다.

```powershell
cd C:\KcwDev\flutter_application_1
flutter pub get
dart format lib
flutter analyze
flutter run
```

기존 `AndroidManifest.xml`은 정상 작동 중인 버전을 유지합니다.

## 우선 테스트 (실기기)

1. DIGITAL 4:3·16:9·1:1 프리뷰가 **여백을 두고** 표시되는지, 비율 왜곡이 없는지.
2. FILM 선택 시 **35mm 글씨와 큰 구멍 없이** 어두운 얇은 필름 게이트가 표시되는지.
3. 줌 접기/펼치기 및 추가 설정 열기가 카메라 미리보기 크기를 바꾸지 않는지.
4. 각 모드에서 사진·영상 촬영 후 JPG/MP4 결과물에 프레임이 일치하는지.
5. 설정에서 디카/필카 프레임 저장을 각각 끄면 저장 결과물에서만 사라지는지.
6. `필터 + 원본 동시 저장` ON에서 원본 파일에는 디자인/필터가 없는지.
7. 동영상 저장 시 프레임 PNG 인코딩 시간 및 프레임 방향이 정상인지.

## 검증 범위 및 남은 제약

- 패키징 시 ZIP 무결성 검사 및 Dart 소스 20개의 문자열/주석을 제외한 괄호 구조 검사를 수행했습니다.
- **실제 Flutter SDK와 Android 실기기가 이 실행 환경에 없어** `flutter analyze`, `flutter run`과 촬영 테스트는 여기서 수행하지 못했습니다. 앱이 반드시 컴파일·실행된다고 보증하지 않습니다.
- 화면 프레임과 저장 프레임은 같은 그리기 코드지만 **사진/영상 필터 색감**은 각각의 처리 엔진을 사용하므로 픽셀 수준의 색 일치는 보장하지 않습니다.
- 영상에 프레임을 기록하려면 기존처럼 FFmpeg 재인코딩이 필요합니다. 단말 사양과 영상 길이에 따라 처리 시간이 늘어납니다.
- 촬영 미리보기 바깥 **카메라 바디 그림자와 기기 베젤**은 앱 UI에만 표시되는 요소입니다. 저장 파일에는 **프레임 내부의 검은 마트와 선**이 들어갑니다. 사진·동영상의 보이는 내용은 선택 비율과 촬영 시 카메라 크롭에 따라 다를 수 있습니다.
