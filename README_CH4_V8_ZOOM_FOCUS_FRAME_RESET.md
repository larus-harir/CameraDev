# CH.4 v8 — 줌/초점 정리, 프레임 디자인 일시 제거

기준: 사용자가 테스트한 CH.4 v7 소스. 기존 DIGITAL S/C/N 및 FILM 프리셋 4개, 사진·동영상 촬영 및 갤러리 저장 기능 유지.

## 1. 줌
- 평소 현재 배율 버튼 1개만 표시. 탭하면 눈금자 펼침.
- 눈금자를 누르면 원하는 배율이 선택되며 **선택 직후 닫히지 않음**.
- **마지막 입력 후 5초**가 지나면 눈금자가 자동으로 닫힘. 현재 배율 버튼을 다시 누르면 즉시 닫음.
- 드래그 중에는 숨김 타이머 중지, 종료 후 다시 시작.
- 눈금자 공간은 항상 고정이어서 열고 닫을 때 뷰파인더 레이아웃이 움직이지 않음.
- 드래그 시 Flutter 측은 작은 ZoomDial 위젯만 갱신하고, CameraX 줌 명령은 최신 값만 보냄.
- CameraX 플랫폼 명령은 최소 120ms 간격으로 제한하고, 실제 명령 수행 시간이 길면 자동으로 간격을 늘림. 드래그 종료 후 최종 배율을 적용. 줌 종료 시 카메라 전체 setState 제거.
- 이것은 **성능 개선 시도**이며 기기 실제 FPS 개선은 실측 필요.

## 2. 터치 포커스
- `AF / AE` 라벨 완전 제거.
- 중앙 점 완전 제거.
- 약 54x54px, 1px 전후의 가는 모서리 선 4개만 표시.
- 게임처럼 튀는 확대/바운스 애니메이션 제거. 간단한 페이드만 유지.
- 약 1.1초 표시 후 사라짐. 실제 AF 잠금 상태를 의미하지 않음.

## 3. 프레임 디자인 보류
- 디카/필카 프레임 장식을 **라이브 미리보기와 JPG/MP4 저장 결과에서 모두 비활성화**.
- 프레임 옵션 UI는 '재작업 중' 표시로 변경해 실제 적용되는 척하지 않음.
- `lib/widgets/frame_artwork.dart`, `renderFrameArtworkPng()`, `FilterService.frameArtwork`, `VideoFilterService.frameArtwork` 등 기반 코드는 **보존**. 재도입 시 디자인만 별도로 작업 가능.
- 새 설정 기본값도 OFF. 기존 설정에서 ON이 저장되어 있어도 CH.4 v8에서는 프레임을 생성하지 않음.
- 카메라 뷰파인더 주변의 기본 검은 바디와 여백은 유지(필름/디카 오버레이만 제거).

## 4. 실제 갤럭시 카메라 수준의 렌즈 전환에 관하여
현재 코드는 `camera` → `camera_android_camerax`의 `setZoomLevel()`을 사용하고, Android CameraX의 `setZoomRatio()`가 실행됩니다.
이는 센서 크롭 기반 확대 등을 포함하는 CameraX 줌 제어이지만, 갤럭시 기본 카메라의 0.6x/1x/3x **물리 렌즈 전환**을 앱이 직접 고르는 것은 아닙니다.
기기가 CameraX 논리 카메라에서 자동 전환할 수도 있으나 보장할 수 없습니다. 따라서 물리 렌즈 전환까지 구현했다고 말하면 안 됩니다.
테스트 로그에 `[CameraLens]`로 CameraX가 열거한 카메라와 지원 줌 범위를 출력합니다. 갤럭시와 동일한 멀티 렌즈 처리 구현을 하려면 별도의 Android 네이티브 코드와 실기기 카메라 특성 확인이 필요합니다.

## 검증 범위
- 현재 환경에서 Flutter SDK, Android 실기기 없음: Flutter 빌드/성능 측정 통과를 주장하지 않습니다.
- ZIP 파일/참조/누락 코드의 정적 구조 검사와 코드 비교만 가능.
- 로그 `[CameraZoom] native update took ...ms`를 통해 네이티브 줌 지연 확인 가능.

테스트 포인트:
1. 현재 배율 탭 후 눈금 선택 가능, 5초 지나야 자동으로 닫힘.
2. 눈금 조작 중 안 닫히고 최종 배율 적용.
3. 포커스 선만 표시되는지.
4. 필카/디카 프레임 미리보기 및 저장 모두 제거되었는지.
5. 1x→2x→3x 줌 FPS가 기존보다 나아졌는지. 카메라 네이티브 명령의 FPS 영향은 남을 수 있음.
